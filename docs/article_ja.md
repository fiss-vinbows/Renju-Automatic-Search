# RASとは？五目並べ・連珠エンジンRapfiの探索を自動で回すツール

**RAS（Renju Automatic Search）は、五目並べ／連珠AI「Rapfi」のGUI「YixinBoard」の探索を、人が付きっきりで操作しなくても自動で進めるためのWindows用補助ツールです。** YixinBoardが出力するデバッグログ（`debuglog.txt`）を読み取って探索状況を判定し、YixinBoardのコマンド入力欄へコマンド（`thinking stop` / `putpos` / `searchdefend` / `nbest`）を送ることで、「時間切れなら最善手を打つ」「全候補が負けなら戻る」といった手順を自動化します。画像認識（OCR）は使いません。

> **要点（30秒でわかる）**
> - 対象：Windows上のYixinBoard（Rapfiエンジン同梱版）
> - 入力：`debuglog.txt`（設定で有効化）／出力：コマンド入力欄へのキー送信
> - できること：探索時間の管理、読み切り（±M）に基づく自動着手・自動巻き戻し、defend探索とnbest探索の交互実行、四への即応
> - できないこと：Rapfiの思考そのものの変更、盤面の画像認識、他のGUI（Piskvork等）への対応

## RASは何を解決するのか

**Rapfiの「防御探索（searchdefend）」や「マルチPV探索（nbest）」は、人が結果を見て次の操作を決める必要があり、長時間の局面研究では手作業が続きます。** RASはその判断と操作を代行します。

| 困りごと | RASの対応 |
|---|---|
| 1時間探索させたあとに最善手を打って次を探索したいが、その場にいられない | 探索時間を設定すると、時間切れで最大評価値の手を自動で着手し、次の探索を始める |
| 全候補が「負け（-M）」と判明した局面は、2手戻して防御をやり直したい | 全候補が-Mになったら自動で`thinking stop` → `undo one` → `searchdefend` |
| 攻める側に勝ち筋（+M）が見つかったら、直前の守り手が悪手なので戻したい | +Mを検出したら着手前の局面へ戻して防御探索をやり直す |
| 四（次に五が揃う）を止めるだけの局面で、わざわざ探索を待ちたくない | 局面から止め手を計算し、探索せずに着手する |

## 仕組み：なぜ画像認識を使わないのか

**YixinBoardは`settings.txt`の「record debug log」を1にすると、GUIとエンジン（`engine.exe`）の全通信を`debuglog.txt`に書き出します。** 盤面上に表示される「39%」「L14」「W7」といった評価表示は、このログ中の候補手ごとの評価情報（`INFO PV`ブロック）から生成されています。RASはこのログを直接読むため、OCRの誤読や取りこぼしがありません。

### 読み取る情報

| ログの項目 | 意味 | RASでの使い方 |
|---|---|---|
| `INFO EVAL` | 候補手の評価値。整数（例`637`）または読み切り表記（`+M14` / `-M14`） | 整数＝評価未確定、`-M`＝負けの読み切り、`+M`＝勝ちの読み切り、として分類 |
| `INFO BESTLINE` | 読み筋。先頭が候補手の座標 | 候補手の位置（例`M13`）に変換 |
| `yxboard` / `yxquerydatabaseallt`に続く座標列 | GUIが送る現在の局面 | 手順の追跡、`putpos`の生成 |
| `EXECUTE_COMMAND : …` | コマンド入力欄やtoolbarから実行されたコマンド | 自分が送ったコマンドの受付確認、人の手動操作の検知 |
| `yxstop` / `yxsearchdefend` / `yxnbest` | エンジン向けの停止・防御探索・マルチPV | 各操作の完了確認 |

### 操作の送り方

**RASはYixinBoardのコマンド入力欄（ログ欄の下のテキスト欄）に文字列とEnterを送ります。** ボタンや盤面のクリックは使いません。利用するコマンドは次の5つです。

| 操作 | コマンド | 備考 |
|---|---|---|
| 停止 | `thinking stop` | 停止時にエンジンが読んでいた最善手が盤面に打たれる（YixinBoardの仕様） |
| 1手戻す | `undo one` | 目標の手数になるまで1回ずつ送る |
| 防御探索 | `searchdefend` | defend探索側の探索を開始 |
| マルチPV探索 | `nbest 2` | nbest探索側の探索を開始 |
| 局面設定（着手） | `putpos h8i9j10…` | 現在の手順＋着手を連結して送る |

`thinking start`は「エンジンが実際に着手する」対局用コマンドのため、RASは使用しません。

## 自動探索のルール（状態と遷移）

**RASは「defend探索側」と「nbest探索側」の2つの状態を持ち、次の条件で遷移します。** 条件の判定は評価値（EVAL）のみで行い、勝率（WINRATE）は使いません。

| 状態 | 条件 | 自動で行う操作 | 次の状態 |
|---|---|---|---|
| defend探索側 | 探索時間が終了し、評価値の付いた候補がある | 停止 → 最大評価値の手を着手 → `nbest 2` | nbest探索側 |
| defend探索側 | 全候補が`-M`（負けの読み切り） | 停止 → 停止前より2手短い局面まで戻す → `searchdefend` | defend探索側 |
| defend探索側 | 最善手以外がすべて`-M` | 停止 → 最善手を着手 → `nbest 2` | nbest探索側 |
| nbest探索側 | `+M`（勝ちの読み切り）を検出 | 停止 → 着手前の局面まで戻す → `searchdefend` | defend探索側 |
| nbest探索側 | 探索時間が終了し、`+M`がない | 停止（エンジンの手が打たれる）→ `searchdefend` | defend探索側 |
| nbest探索側 | 最善手以外がすべて`-M` | 停止 → 最善手を着手 → `searchdefend` | defend探索側 |
| どちらでも | 相手の四を止めるしかない局面 | 探索を待たずに止め手を着手（連鎖する場合はまとめて） | 手番に応じて |

### 「戻る回数」の考え方

`thinking stop`を送るとエンジンの手が1手追加されるため、「n手の局面でn+1手目を探索中に全候補が-M」の場合、n−2手の局面へ戻すには`undo one`を通常3回送ります。RASは回数ではなく**目標の手数に達するまで**1回ずつ送り、目標を通り過ぎた場合は停止します。

## 2つの探索モード

| モード | 内容 | 設定項目 |
|---|---|---|
| **nbest探索あり**（既定） | defend探索側（`searchdefend`）とnbest探索側（`nbest 2`）を交互に行う | defend探索側の探索時間、nbest探索側の探索時間、nbest候補手数 |
| **nbest探索なし** | 双方とも`searchdefend`で探索する | 探索時間（1つ、双方共通） |

nbest探索なしモードでは、`+M`を検出した場合を「直前の相手の手が悪手」とみなして1手戻し、`searchdefend`をやり直します。

## セットアップ手順

**所要時間は5分程度です。追加ライブラリのインストールは不要です。**

1. YixinBoardを終了した状態で`settings.txt`を開き、`;record debug log`の行の値を`0`から`1`に変更する
2. YixinBoardのフォルダ直下に`RAS`フォルダを作り、`RAS.exe`・`monitor_config.json`・`sender_config.json`を置く
3. YixinBoardを起動し、`RAS.exe`を起動する
4. 初回のみ「入力欄を校正」を押し、5秒以内にマウスカーソルをYixinBoardのコマンド入力欄の上に置く（ウィンドウサイズを変えたら再校正）
5. 探索モードと探索時間を設定し、「設定を保存」
6. 「自動探索モード」のトグルをオンにする
7. YixinBoardのコマンド入力欄で`searchdefend`（または`nbest 2`）を実行する。以後は自動で進む

止めるときはトグルをオフにします。YixinBoard側を手動で操作した場合も、自動探索モードは自動的にオフになります。

## 設定項目の一覧

設定はGUIから編集でき、`monitor_config.json`に保存されます。

| 項目 | 既定値 | 説明 |
|---|---|---|
| defend探索側 探索時間（秒） | 3600 | `searchdefend`の制限時間。経過したら最大評価値の手を着手してnbest探索側へ |
| nbest探索側 探索時間（秒） | 1800 | `nbest`の制限時間。経過したら停止し、エンジンの手を採用してdefend探索側へ |
| 探索時間（秒）〔nbest探索なしモード〕 | 3600 | 双方共通の`searchdefend`制限時間 |
| 安定確認 周回数 | 3 | 「全候補が負け」「最善手以外が負け」の成立に必要な連続周回数 |
| 安定確認 最低秒数 | 10 | 同上の成立に必要な探索開始からの最低経過秒数。`-M`は読み切り結果のため2〜3秒で十分 |
| 操作タイムアウト（秒） | 20 | コマンド送信後、完了確認をこの秒数待って取れなければ停止 |
| nbest候補手数 | 2 | nbest探索側で送る`nbest`の候補数 |

## 安全設計：誤操作を防ぐ仕組み

**自動操作ツールで最も避けるべきなのは「盤面を壊す」「他のアプリに文字を打つ」ことです。** RASは次の対策を実装しています。

- **受付確認と完了確認**：送ったコマンドは`EXECUTE_COMMAND`行で受付を、`yxstop`などのエンジン向けコマンドや局面の送り直しで完了を確認する。4秒以内に受付が取れなければ1回だけ再送（`undo one`は二重実行が危険なため再送しない）
- **`putpos`の二重チェック**：現在の局面が不明（0手）のとき、または送る手順が現在より長くないときは送信せず停止
- **戻しすぎの検知**：`undo one`は目標手数に達するまで1回ずつ送り、目標より短くなったら停止
- **前面ウィンドウの確認**：送信直前に前面がYixinBoardでなければ送らない。他アプリへのキー注入（Altキー等）は行わない
- **手動操作の検知**：自動探索中に人がYixinBoardを操作したら自動探索モードをオフにする
- **想定外の状態で停止**：defend探索側で`+M`が出る、解釈できない評価値が出る、などの場合は停止して理由を表示

## 制限事項・既知の注意点

- **送信の瞬間（約0.3〜0.5秒）はYixinBoardが前面になり、マウスカーソルが動きます。** YixinBoard（GTK製）は非アクティブ時のキー入力を受け付けないため、前面化と入力欄のクリックは省略できません。送信後は元のウィンドウとカーソル位置に戻します
- **`debuglog.txt`は探索中に増え続けます**（実測で約30MB/時間）。YixinBoard起動中でもGUIの「ログを切り詰め」で安全に空にできます
- **四の判定は簡易実装です。** 相手が次に五を作れる空点がちょうど1つ、かつ自分に五がない場合のみ着手します。連珠の禁手は考慮していません
- **Windows専用**です。Norton等のセキュリティソフトがPyInstaller製のexeを誤検知することがあります
- 探索時間が短い設定（数十秒）では、深い探索の1周回（10秒以上）に安定確認が間に合わないことがあります。時間切れ時点で全候補が`-M`なら「全候補が負け」として扱います

## よくある質問（FAQ）

### Q. RASはRapfiの強さや思考を変えますか？
**いいえ。** RASはYixinBoardのコマンドを送るだけで、エンジンの探索内容には一切関与しません。

### Q. 画像認識（OCR）は使っていますか？
**使っていません。** YixinBoardの`debuglog.txt`を読み取ります。当初は盤面のOCRを試作しましたが、「L」の文字が数字と融合して誤読する問題が解決せず、ログ読み取り方式に切り替えました。

### Q. 勝率（%）ではなく評価値で判定するのはなぜですか？
評価値が整数の候補手は「探索継続中で未確定」、`±M`の候補手は「勝敗が確定した読み切り」という意味の違いがあり、判定にはこの区別だけが必要だからです。

### Q. `thinking stop`を送るとエンジンが勝手に1手打ちますが問題ありませんか？
YixinBoardの仕様で、停止時に読んでいた最善手が盤面に打たれます。RASはこれを前提に「戻る回数」を目標手数で制御し、着手が必要な場面では`putpos`で局面を丸ごと置き換えるため問題ありません。

### Q. 離席中に止まっていました。どうすれば原因が分かりますか？
GUIのログ欄と`output\monitor_log.jsonl`（JSON Lines形式の判定ログ）に、停止理由と直前の候補手一覧が残ります。

### Q. 他の五目並べGUI（Piskvorkなど）でも使えますか？
使えません。YixinBoardの`debuglog.txt`の形式とコマンド入力欄に依存しています。

## 用語集

| 用語 | 定義 |
|---|---|
| **Rapfi** | 五目並べ・連珠向けの探索エンジン。YixinBoardに`engine.exe`として同梱される |
| **YixinBoard（Yixin）** | Rapfiを操作するGTK製GUI。`Yixin.exe` |
| **debuglog.txt** | `settings.txt`の「record debug log」を1にするとYixinBoardが書き出す、GUIとエンジンの全通信ログ |
| **searchdefend（防御探索）** | 手番側の守り手を探索するYixinBoardのコマンド。RASでは「defend探索側」の探索 |
| **nbest（マルチPV）** | 上位N手を並行して探索するYixinBoardのコマンド。RASでは「nbest探索側」の探索 |
| **EVAL** | 候補手の評価値。整数、または`+M数字`（数字手で勝ち）／`-M数字`（数字手で負け） |
| **putpos** | 手順文字列（例`h8i9j10`）で局面を設定するYixinBoardのコマンド |
| **四** | 次に1手で五が揃う形。止め手が実質1通りならRASは探索せず着手する |

## まとめ

**RASは、YixinBoardの探索ログとコマンド入力欄という「GUIに元から備わっている機能」だけを使い、Rapfiの長時間探索を人の判断なしで進めるツールです。** 画像認識を使わないため判定が正確で、受付確認・完了確認・戻しすぎ検知などの安全策により、離席中でも盤面を壊さずに探索を続けられます。設定はGUIから変更でき、nbest探索あり／なしの2モードに対応しています。

*本記事は2026-09-18時点のRASの仕様に基づいています。*
